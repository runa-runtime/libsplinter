# Splinter 1.2.1 (LTS) — Changelog

Notable changes since the 1.2.0 release (`45b451e`). This is a maintenance
release on the LTS line: no new subsystems and no format change, but the event
bus now scales past 1024 slots, several write paths that were silently failing
to signal watchers now do, and `splinter_set()` finally honors its documented
`errno` contract. 12 commits in total; the highlights are below.

## Highlights

- **The event bus dirty mask now scales to any store size** — slot indices are
  mapped in contiguous stripes instead of folded modulo 1024.
- **Label transitions reach signal-group subscribers** — `splinter_set_label()`
  and `splinter_unset_label()` were never pulsing watchers, silently breaking
  the documented `WAITING → SERVICING → READY` handshake.
- **The eventfd is non-blocking** — a saturated counter can no longer stall a
  writer inside `splinter_set()`.
- **`splinter_set()` sets `errno`** — `ENOSPC`, `EMSGSIZE`, `EINVAL` and
  `EOVERFLOW` instead of a bare `-1` over a stale value.
- No on-disk format change: `SPLINTER_VER` remains 4 and existing stores open
  unchanged.

---

## Event bus — striped dirty mask

`SPLINTER_MAX_SLOTS` was never a cap on slots per store; nothing ever checked it
against `splinter_create()`'s slot count, and stores far larger than 1024 have
always been legal. It only ever sized the event bus dirty mask. Above 1024 slots
the mask folded indices modulo 1024, so a set bit meant "some slot congruent to
*k* mod 1024 changed" — a residue class scattered across the whole store.

Slots are now divided into contiguous stripes of
`ceil(slots / SPLINTER_EVENT_BUS_BITS)`, so bit *k* covers
`[k*stripe, (k+1)*stripe)` and a watcher rescans a short sequential run instead
of hopping across the store. At 1024 slots or fewer the stripe is 1 and the
mapping is exact, identical to prior behavior.

The mask stays a fixed 1024 bits (128 bytes) so it remains cache-resident; the
stripe width is computed once per mapping rather than on the write hot path.

- `SPLINTER_MAX_SLOTS` is renamed to **`SPLINTER_EVENT_BUS_BITS`**. The old name
  is retained as a deprecated alias, so existing sources and generated bindings
  keep compiling.
- New `splinter_event_bus_stripe()` — slots covered per mask bit; call this
  rather than rederiving the rounding.
- New `splinter_event_bus_take_dirty()` — snapshot and clear in one atomic step.
  The mask is OR-only and `splinter_event_bus_get_dirty()` never clears it, so a
  consumer that did not diff against its own saved copy would watch the mask
  saturate to all-ones and stop discriminating. Destructive to other watchers,
  and classified MEDIUM risk for that reason; `get_dirty()` keeps its
  non-destructive contract for multi-reader use.

## Signal delivery — write paths that never pulsed

`splinter_pulse_watchers()` is the only thing that routes a slot's bloom through
`H->bloom_watches[]` into a signal group, so a write path that skips it is
invisible to anyone who subscribed with `splinter_watch_label_register()`.
Several paths the risk topology already documented as "watchers pulsed" did not.

- **`splinter_set_label()` / `splinter_unset_label()`** now pulse. This is the
  delivery step for the documented label lifecycle; without it the handshake
  only worked for consumers polling `splinter_enumerate_matches()` on a timer.
  `unset_label()` deliberately routes by the **pre-clear** bloom — the whole
  point of clearing a label is to tell whoever was bound to it that the state
  moved on, and routing by the post-clear bloom would wake every subscriber
  except that one.
- **`splinter_set_embedding()`, `splinter_set_named_type()`,
  `splinter_integer_op()`** now pulse; group subscribers previously missed
  vector writes, type promotions and integer ops entirely.
- **`splinter_unset()`** now pulses watchers, advances the global epoch and
  notifies the event bus. It signalled on neither channel before. Because
  teardown zeroes `watcher_mask` and `bloom`, the routing masks are captured
  before the clear and pulsed once the seqlock closes.

## errno contract

- `splinter_set()` sets **`ENOSPC`** when the store is genuinely full. It
  previously returned a bare `-1`, leaving `errno` holding whatever an unrelated
  earlier call left there — a caller following the documented contract read a
  stale value as a real answer.
- It also distinguishes a full store from transient contention. The probe skips
  slots whose seqlock is held, so exhausting it does not on its own prove there
  is no room: if any candidate was busy you now get **`EAGAIN`** (retry), and
  only if none were do you get `ENOSPC` (give up).
- Oversized values set **`EMSGSIZE`**, zero-length values set **`EINVAL`**, and
  a slot whose value offset falls outside the arena sets **`EOVERFLOW`**.

## Core changes & bug fixes

- The eventfd is created `EFD_NONBLOCK`. Writers pulse it from inside
  `splinter_set()` and friends; a blocking fd whose counter saturated with no
  reader draining would wedge the writer mid-write, stalling every reader queued
  behind it. Dropping the write is lossless — the dirty mask carries the state
  and the fd is only a doorbell.
- `splinter_event_bus_wait()` now returns `-1` rather than blocking
  indefinitely when two waiters race and one drains the counter first.
  `O_NONBLOCK` lives on the open file description shared by every fd handed out
  for a bus, so this affects `dup()` and `pidfd_getfd()` clients alike.
- The `bloom_watches` initialization loop is hoisted out of the per-slot loop in
  `splinter_create()`. It was rewriting all 64 header entries once per slot —
  identical values every pass. Measured ~13% off a 200k-slot create.
- `splinter_purge()` and `splinter_set_slot_time()` are reclassified in the risk
  topology to match what they actually do: `purge()` touches every slot and does
  not pulse (signalling per slot would be a wake storm, and it only scrubs bytes
  already past `val_len`), and `set_slot_time()` is metadata-only.

## CLI command improvements

- **`init`** — store paths are no longer silently truncated into a 64-byte
  buffer. `snprintf()` never reports truncation, so an over-long path was cut
  and handed to `splinter_create()` with rc still 0; a 155-byte path produced a
  fully-formed store in a different directory, exit 0, no warning. Over-long
  paths are now refused with `ENAMETOOLONG`.
- **`orders set`** — the printed word and the exit code no longer disagree. A
  failed tandem write used to print `FAIL` and still exit 0, so a caller
  trusting `$?` would carry on writing into a tandem that was never set.

## Build & packaging

- New `scripts/install_wasmEdge.sh` — builds and installs WasmEdge from source
  for `--with-wasm` builds, with `--ref`, `--prefix` and `--yes` flags plus
  `WASMEDGE_REF` / `PREFIX` / `SRC_ROOT` environment overrides.

## Rust bindings

- Republished at 1.2.1. The vendored C sources pick up the striped dirty mask,
  the new signal-delivery behavior and the `errno` contract; bindgen emits
  `SPLINTER_EVENT_BUS_BITS`, the retained `SPLINTER_MAX_SLOTS` alias, and the
  two new event bus functions.
- Note that `scripts/sync-rust-vendor.sh` is a manual step and copies `build.h`
  as well as the core sources, so it must be run *after* `scripts/genbuildh`.

## Documentation

- New API pages for `splinter_event_bus_take_dirty` and
  `splinter_event_bus_stripe`; `splinter_event_bus_get_dirty` and
  `splinter_event_bus_wait` updated for striping and the non-blocking fd.
- The AI Primer in `splinter.h` documents the stripe geometry, the expanded
  `errno` model, and the corrected risk classifications.
- Docs site: assets and head/plugin updates, favicon cleanup.
